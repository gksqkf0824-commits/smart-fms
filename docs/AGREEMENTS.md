# 합의사항 (AGREEMENTS)

> 팀 공통 결정 사항. **변경 시 반드시 팀 논의 후 이 문서부터 수정.**
> 헷갈리면 여기부터 확인 부탁드립니다. (상세 API 규약은 `API.md`, DB는 `ERD.md`)

---

## 1. 시스템 개요

카셰어링·무인 모빌리티 차량의 **실내 오염·이물질**을 AI로 분석 →
오염도에 따라 **배차 중단 · 차량 Swap · 패널티 · 세차 자동 호출 · 유실물 알림**까지
사람 개입 없이 처리하는 무인 FMS.

---

## 2. 이미지 처리 흐름

```
① 폰/카메라 → Spring Boot   (사진 원본 업로드)
② Spring Boot            (형식 검증·JPG 통일 → 얼굴·번호판 마스킹)
③ Spring Boot → S3        (마스킹본만 저장)
④ Spring Boot → FastAPI   (분석 요청: 이미지 전달)
⑤ FastAPI → Spring Boot   (분석 결과 JSON 반환 — 이미지 X)
⑥ Spring Boot            (등급 판정 → 배차/세차/패널티/알림)
⑦ Spring Boot → DB        (기록) → 대시보드 반영
```

- **이미지 방향:** 백엔드 → AI. AI는 **결과 JSON만** 반환하고 이미지는 돌려주지 않음.
- **백엔드가 지휘자(orchestrator):** 사진 저장·AI 호출·판정·알림·기록을 모두 백엔드가 통제.

---

## 3. 이미지 저장 규칙

- 이미지 **파일**은 **S3**에 저장.
- **DB(PostgreSQL)에는 S3 경로(key/URL)만** 문자열로 저장. **이미지 바이너리(BLOB) 저장 금지.** → DB 부하 방지.
- 대시보드 조회 시 **presigned URL**(임시 접근 링크) 발급.

예시: `image_key = "inspections/2026/12가3456_0941.jpg"` (경로만 저장)

---

## 4. 입력 이미지 형식

- **허용 형식:** JPG, PNG, HEIC (아이폰·안드로이드 촬영 모두 대응).
- **처리 위치:** 백엔드 수신 단계에서 검증·변환. 허용 형식 → **JPG로 통일** 후 S3 저장·AI 전달.
- 미지원 형식·용량 초과 → `400` 에러. **AI 서버는 JPG를 받는다고 가정.**

---

## 5. 개인정보 마스킹

- 차량 실내엔 탑승자 얼굴·번호판이 찍힐 수 있으므로, **S3 저장 전** 백엔드에서 마스킹.
- **원본은 서버·S3에 남기지 않음** (마스킹본만 저장).
- 오염·이물질은 시트·바닥에 있으므로 얼굴 마스킹이 AI 성능에 영향 없음.
- **PoC 범위:** 시연은 시트·바닥만 촬영해 얼굴이 안 들어오므로, 마스킹은 **개념 설계로 명시**하고 실제 구현은 후순위(시간 여유 시).

---

## 6. AI 모델 & 분석 (모델 2개)

| 모델 | 파일 | 감지 | 방식 |
|---|---|---|---|
| Detection | `trash_occupy_detection_best.pt` | `trash`(쓰레기), `occupy`(소지품/유실물) | 박스 — **개수·크기** |
| Segmentation | `stain_seg.pt` | `spill`(오염) | 마스크 — **면적 비율** |

- **오염 면적 비율** = ROI(시트·바닥) 안의 오염 마스크 픽셀 ÷ ROI 전체 픽셀. (분모는 화면 전체가 아닌 ROI)
- ROI는 카메라 구도 고정이라 **좌표로 사전 정의** (AI팀 ↔ PM 합의).
- **값 형식:** 비율 값은 모두 **0.0~1.0**으로 주고받음. 화면 % 표시는 프론트가 ×100.
- **AI는 raw 값만 반환**, 등급(grade) 판정은 **백엔드**가 함.

---

## 7. 등급 판정 로직 (백엔드)

> 쓰레기(개수)와 오염(면적)은 **독립 평가 후 더 심각한 상태로 통합(Overriding).**

**Track 1 — 쓰레기**
| 조건 | 판정 |
|---|---|
| 대형(ROI 1%↑) 1개 이상 | `BLOCK` |
| 개수 3개 이상 | `BLOCK` |
| 소형 1~2개 | `WARN` |

**Track 2 — 오염 (`roi_pollution_ratio`, 0~1)**
| 조건 | 판정 |
|---|---|
| ≥ 0.05 (5%) | `BLOCK` |
| 0.02~0.05 (2~5%) | `WARN` |
| < 0.02 | `NORMAL` |

**통합:** Track 1·2 중 더 심각한 상태로. 단, **둘 다 `WARN`이면 `WARN`.**
**소지품(`occupy`):** grade에 영향 없음 → 감지 시 `user_alert=true`로 유실물 알림만.

> **임계치 근거:** 면적 비율 정량화·등급화 *방법론*은 식물병·산업결함 진단 등에서 확립된 접근.
> 단, 5%·3개 같은 *임계치 수치*는 학술값이 아닌 **운영 정책 파라미터** → 하드코딩 아닌 설정값으로 분리, 데이터로 보정 전제.

## 8. AI 서빙

- AI 추론은 **FastAPI 독립 REST 서버**로 분리 (파이썬 ML ↔ 자바 백엔드).
- 백엔드와 **JSON**으로 통신. (스펙은 `API.md`)

---

## 9. 프론트엔드

- **모바일 웹** (네이티브 앱 X). 카메라는 웹 표준 API로 촬영.
  - 이유: 실제 촬영은 인캐빈 카메라가 담당 → 고객용 앱 필요성 낮음.
- 실제 환경은 **인캐빈 카메라 1대**, 시연은 **모바일 카메라로 대체**.
- 화면 스코프: **시연 플로우 3화면(번호→촬영→결과) + 대시보드 2화면(리스트→상세)**. 통계 페이지는 1순위 컷 대상.

---

## 10. 알림

- 오염·이물질 감지(임계치 초과) 시 **디스코드 Webhook** 자동 발송.
- 대시보드 화면 알림(FE)과는 별개 — 채널 푸시 알림은 백엔드(PM)가 담당.

---

## 11. 협업 규칙

- 브랜치: `ai` / `backend` / `frontend` / `infra` (파트별) → **`develop`으로 통합** → 막판 `main`.
- 문서(README, `docs/`)는 `main`에서 관리 (공용 참조).
- 가끔 `git merge develop`으로 최신 반영 (충돌 예방).
- **커밋 금지:** 모델 가중치(`.pt`), 데이터셋, `.env` → `.gitignore` 확인.
