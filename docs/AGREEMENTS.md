# 합의사항 (AGREEMENTS)

> 팀 공통 결정 사항. **변경 시 반드시 팀 논의 후 이 문서부터 수정.**
> 헷갈리면 여기부터 확인하세요.

---

## 1. 시스템 개요

카셰어링·무인 모빌리티 차량의 **실내 오염**을 AI로 픽셀 단위 분석 →
오염도에 따라 **배차 중단 · 차량 Swap · 패널티 · 세차 자동 호출**까지
사람 개입 없이 처리하는 무인 FMS.

---

## 2. 이미지 처리 흐름

```
① 폰/카메라 → Spring Boot   (사진 원본 업로드)
② Spring Boot            (얼굴·번호판 마스킹)
③ Spring Boot → S3        (마스킹본만 저장)
④ Spring Boot → FastAPI   (분석 요청: 이미지 or S3 key 전달)
⑤ FastAPI → Spring Boot   (오염도 결과 JSON 반환 — 이미지 X)
⑥ Spring Boot            (오염도 등급 판정 → 배차/세차/알림)
⑦ Spring Boot → DB        (기록) → 대시보드 반영
```

- **이미지 방향:** 백엔드 → AI. AI는 **결과 JSON만** 반환하고 이미지는 돌려주지 않음.
- **백엔드가 지휘자(orchestrator):** 사진 저장·AI 호출·판정·알림·기록을 모두 백엔드가 통제.

---

## 3. 이미지 저장 규칙

- 이미지 **파일**은 **S3**에 저장.
- **DB(PostgreSQL)에는 S3 경로(key/URL)만** 문자열로 저장. **이미지 바이너리(BLOB) 저장 금지.**
  → DB 부하 방지.
- 대시보드 조회 시 **presigned URL**(임시 접근 링크) 발급.

예시 (inspection 레코드):
```
image_key = "inspections/2026/12가3456_0941.jpg"   // ← 경로만 저장
```

---

## 4. 개인정보 마스킹

- 차량 실내엔 탑승자 얼굴·번호판이 찍힐 수 있으므로, **S3 저장 전** 백엔드에서 마스킹.
- **원본은 서버·S3에 남기지 않음** (마스킹본만 저장).
- 오염(쓰레기·액체·얼룩)은 시트·바닥에 있으므로 얼굴 마스킹이 AI 성능에 영향 없음.
- **PoC 범위:** 시연은 시트·바닥만 촬영해 얼굴이 안 들어오므로, 마스킹은 **개념 설계로 명시**하고
  실제 구현은 후순위(시간 여유 시).

---

## 5. AI / 오염도 정량화

- **오염도(%) = ROI(시트·바닥) 안의 오염 마스크 픽셀 수 ÷ ROI 전체 픽셀 수**
  - 분모는 화면 전체가 아닌 **ROI** (천장·창문 등 무의미 영역 제외).
  - ROI는 카메라 구도가 고정이므로 **좌표로 사전 정의** (AI팀 ↔ PM 합의).
- **클래스 2종:** `trash`(고형 쓰레기: 휴지·컵·포장 등) / `spill`(액체·얼룩)
- **임계치**(예: 10% / 30%)는 **운영 정책값** → 코드에서 설정값으로 분리, 하드코딩 금지.
- **모델:** YOLO11-Seg 베이스라인 (Mask R-CNN 비교군).
- **정확도 검증:** IoU / Dice.

### 오염도 → 조치 매핑 (초안, 임계치는 조정 가능)
| 합산 오염도 | 조치 |
|---|---|
| ~10% | 정상 (조치 없음) |
| 10~30% | 경고 + 패널티 등록 |
| 30%~ | 배차 차단 + Swap + 세차 호출 |
| (별도) `spill` 감지 시 | 양이 적어도 세차 필요 → 세차 호출 |

## 6. AI 서빙

- AI 추론은 **FastAPI 독립 REST 서버**로 분리 (파이썬 ML ↔ 자바 백엔드).
- 백엔드와 **JSON**으로 통신. (스펙은 `API.md`)

---

## 7. 프론트엔드

- **모바일 웹** (네이티브 앱 X). 카메라는 웹 표준 API로 촬영.
  - 이유: 실제 촬영은 인캐빈 카메라가 담당 → 고객용 앱 필요성 낮음.
- 실제 환경은 **인캐빈 카메라 1대**, 시연은 **모바일 카메라로 대체**.
- 화면 스코프: **시연 플로우 3화면(번호→촬영→결과) + 대시보드 2화면(리스트→상세)**.
  통계 페이지는 1순위 컷 대상.

---

## 8. 알림

- 오염 감지(임계치 초과) 시 **디스코드 Webhook** 자동 발송.
- 대시보드 화면 알림(FE)과는 별개 — 채널 푸시 알림은 백엔드(PM)가 담당.

---

## 9. 협업 규칙

- 브랜치: `ai` / `backend` / `frontend` / `infra` (파트별) → **`develop`으로 통합** → 막판 `main`.
- 문서(README, `docs/`)는 `main`에서 관리 (공용 참조).
- 가끔 `git merge develop`으로 최신 반영 (충돌 예방).
- **커밋 금지:** 모델 가중치(`.pt`), 데이터셋, `.env` → `.gitignore` 확인.
