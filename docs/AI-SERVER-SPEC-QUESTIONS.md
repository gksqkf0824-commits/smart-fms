# AI 서버 구현 중 확인 요청

> 회의: 2026-08-30 · 작성: AI 서버 파트 · 기준 문서: `docs/API.md` (2026-08-29)

`API.md` 8/29 판(2모델 구조)에 맞춰 `/predict`를 구현하면서 확인이 필요한 두 가지입니다.
1번은 구현이 막혀 있는 건이고, 2번은 제안입니다.

---

## 1. ROI 좌표 정의 요청 (구현 블로킹)

### 현황

`API.md`는 두 값을 **ROI 기준**으로 정의하고 있습니다.

| 필드 | 명세 문구 |
|---|---|
| `roi_pollution_ratio` | 오염 픽셀 / **ROI 전체 픽셀** |
| `trash_large` | **ROI의 1% 이상** 차지하는 대형 쓰레기 존재 여부 |

`AGREEMENTS.md` §5도 같은 취지입니다.

> 분모는 화면 전체가 아닌 **ROI** (천장·창문 등 무의미 영역 제외).
> ROI는 카메라 구도가 고정이므로 **좌표로 사전 정의** (AI팀 ↔ PM 합의).

그런데 **ROI 좌표가 아직 정의된 적이 없습니다.** 그래서 현재 구현은 두 값 모두 **화면 전체**를 분모로 쓰고 있고, 이는 명세와 다릅니다.

### 왜 지금 정해야 하나

분모가 달라지면 값이 그대로 스케일됩니다. ROI가 화면의 40%라면 실제 오염도가 **2.5배 희석**되어 나옵니다.

| | ROI 기준 (명세) | 화면 전체 기준 (현재 구현) |
|---|---|---|
| 시트 위 얼룩이 ROI의 8%를 덮음 | `0.08` → **BLOCK** | `0.032` → WARN |

`API.md` §2의 BLOCK 임계값이 `0.05`이므로, 이대로 두면 **차단돼야 할 차량이 경고로 빠집니다.** 백엔드 판정 로직을 아무리 정확히 짜도 입력값이 어긋나 있으면 소용이 없습니다.

### 요청

- 인캐빈 카메라 구도 기준 **ROI 좌표(시트·바닥 영역)를 확정**해 주세요.
- 형식은 정규화 좌표(예: `[[0.1, 0.45], [0.9, 0.45], [0.9, 1.0], [0.1, 1.0]]`)면 해상도와 무관하게 쓸 수 있습니다.
- 확정 전까지는 화면 전체를 분모로 쓰되, **그 사실을 `API.md`에 한 줄 명시**해 두는 편이 안전합니다. 백엔드가 임계값을 튜닝할 때 전제를 알아야 합니다.

## 2. `400 unsupported_image_format` 추가 제안

### 현황

현재 `API.md`에는 `no_target_detected` 외 에러 규격이 없습니다.
(`ai` 브랜치에 최지우 님이 8/16에 정리한 에러 표가 있지만 main에 머지되지 않았고, main 기준으로 진행하는 것으로 알고 있어 **복원이 아니라 신규 제안**으로 올립니다.)

실제로 요청을 보내 측정한 현재 동작입니다.

| 입력 | 현재 응답 | 문제 |
|---|---|---|
| PNG · JPEG | `200` | 정상 |
| **BMP** (스펙 미허용) | `200` | 허용 안 한 포맷이 조용히 통과 |
| **HEIC** (아이폰 기본) | `500` | 디코딩 불가인데 서버 장애로 보고 |
| **PDF 등 비이미지** | `500` | 클라이언트 잘못이 서버 장애로 보고 |
| **잘린 · 손상된 이미지** | `500` | 동일 |

즉 **허용하지 않는 포맷은 통과시키고, 깨진 파일은 서버 장애로 보고**합니다.

### 400이 없으면 생기는 일

1. **고객이 반납을 끝내지 못합니다.** `/return`은 AI 서버 오류 시 프론트에 재시도 버튼을 띄우는데, 원인이 "이 파일은 이미지가 아니다"면 몇 번을 눌러도 같습니다. 아이폰 HEIC가 그대로 넘어오는 경우가 가장 현실적입니다.
2. **진짜 장애가 알람에 묻힙니다.** 5xx는 "서버가 아프다"는 지표라 알람을 거는데, 고객이 올린 깨진 파일이 섞이면 실제 모델 다운이 노이즈에 가려집니다.
3. **책임 소재가 흐려집니다.** 500이면 AI 서버 버그부터 뒤지게 되는데, 실제로는 업로드 경로 문제인 경우가 많습니다.

### 제안 규격

| 상황 | 응답 | `detail` |
|---|---|---|
| JPEG/PNG가 아니거나 디코딩 불가 | `400` | `unsupported_image_format` |
| `image` 누락 · 빈 파일 | `422` | `image field required` |
| 탐지 결과 없음 | `200` | `no_target_detected` |
| 추론 중 서버 오류 | `500` | `inference_failed` |

백엔드는 400을 재시도 대상에서 빼고 "지원하지 않는 사진 형식입니다" 안내로 분기하면 됩니다.

### 함께 정할 것

**HEIC를 지원할까요?** 아이폰 기본 촬영 포맷이라 그대로 두면 실사용에서 가장 자주 부딪힙니다.
→ **백엔드 변환을 권합니다.** 마스킹·S3 저장을 이미 거치므로 그 단계에서 함께 처리하는 편이 자연스럽습니다.
